# 04 — 平台集成与配置

## 1. 本步目标

将 **vLLM Qwen 7B** 与 **PaddleOCR-VL 1.6** 接入现有 **Economic Agent Platform**：

- 聊天 / Agent 默认走自建 `custom` Provider  
- 知识库 PDF/图片入库走 PaddleOCR-VL  
- 聊天附件解析可走 OCR 服务（替代或补充现有 `vlm.py` 启发式路径）  

---

## 2. 部署拓扑（推荐）

```
┌─────────────────────────┐         内网          ┌─────────────────────────┐
│ 轻量 4核8G / 同 GN7      │ ◄──────────────────► │ GN7 T4（若拆分则跨 VPC） │
│ docker-compose.prod      │   CUSTOM_BASE_URL    │ vLLM :8000              │
│ :8082 对外               │   PADDLE_OCR_VL_URL  │ PaddleOCR :8080         │
└─────────────────────────┘                      └─────────────────────────┘
```

若 **GN7 单机全栈**：backend 与 vLLM 同机，`CUSTOM_BASE_URL=http://127.0.0.1:8000/v1`。

## 3. 环境变量配置

复制 `deploy/env.production.template` → `.env`，修改：

```env

DEFAULT_LLM_PROVIDER=custom

CUSTOM_API_KEY=not-needed
CUSTOM_BASE_URL=http://<GPU内网IP>:8000/v1
CUSTOM_MODEL=qwen7b-accounting

# 若 vLLM 使用 LoRA 模块名
# 前端设置页 model 填 accounting 或与 --served-model-name 一致

# --- 可选：DeepSeek 留作灾备 ---
DEEPSEEK_API_KEY=
# DEFAULT_LLM_PROVIDER=deepseek  # 回滚时切换

# --- PaddleOCR-VL 文档解析服务（新增，集成改造后生效）---
PADDLE_OCR_VL_ENABLED=true
PADDLE_OCR_VL_URL=http://<GPU内网IP>:8080
PADDLE_OCR_VL_PARSE_PATH=/v1/doc/parse

# --- 其余保持 docker-compose 默认 ---

AGENT_STREAMING_ENABLED=true
```

**跨机部署**：平台 Docker 容器需能访问 GPU 机 IP（同一 VPC / 安全组放行）。

## 4. 后端代码改造点

> 以下为 **建议实施顺序**；按最小可用路径先接通 LLM，再替换 OCR。

### 4.1 Phase 1 — 仅切换 LLM（无需改代码）

平台已支持 `custom` Provider（`backend/app/core/config.py`）。

1. 部署 vLLM  
2. 修改 `.env` 中 `DEFAULT_LLM_PROVIDER=custom`  
3. 重启 backend：`docker compose ... restart backend`  
4. 前端 **设置 → 模型**：Provider 选 `custom`，Model 填 `qwen7b-accounting`  

验证：WebSocket 聊天 `/ws/chat/{session_id}` 返回微调风格回答。

### 4.2 Phase 2 — PaddleOCR-VL 接入 ingestion

**新增客户端** `backend/app/ingestion/paddleocr_vl/client.py`：

```python
import httpx
from app.core.config import config  # 或 os.getenv

async def parse_document_bytes(raw: bytes, filename: str) -> dict:
    url = f"{os.getenv('PADDLE_OCR_VL_URL')}{os.getenv('PADDLE_OCR_VL_PARSE_PATH', '/v1/doc/parse')}"
    async with httpx.AsyncClient(timeout=120.0) as client:
        files = {"file": (filename, raw)}
        r = await client.post(url, files=files)
        r.raise_for_status()
        return r.json()
```

**修改** `backend/app/ingestion/media/service.py` 中 `prepare_media_ingest` / `parse_image_bytes`：

- 当 `PADDLE_OCR_VL_ENABLED=true` 时，图片/PDF 页优先调用 `parse_document_bytes`  
- 将返回的 `markdown` 写入 `plain_text` / chunk，供 RAG 索引  
- 失败时 **fallback** 现有 OCR + 启发式 VLM（`ocr.py` / `vlm.py`）  

**修改** `backend/app/jobs/tasks.py` 中 `run_media_ingest` / `run_pdf_ingest`：

- PDF 逐页或整文档送 PaddleOCR-VL（按官方推荐粒度）  

### 4.3 Phase 3 — 聊天附件（可选）

**修改** `backend/app/services/attachment_service.py`：

- 对 `kind=image` 且为文档类（报表、票据）调用 PaddleOCR-VL  
- 将 `markdown` 填入 `ocr_text` / `text_preview` 字段供非视觉 LLM 使用  

前端无需改动（仍传 `asset_id`）。

### 4.4 配置注册

在 `backend/app/core/config.py` 或独立 `settings` 中增加：

```python
paddle_ocr_vl_enabled: bool = os.getenv("PADDLE_OCR_VL_ENABLED", "false").lower() == "true"
paddle_ocr_vl_url: str = os.getenv("PADDLE_OCR_VL_URL", "")
```

并写入 `deploy/env.production.template` 模板。

## 5. 前端与设置页

`frontend` 已从 WebSocket 传递 `provider` / `model`（`ChatView.vue` → `chat.ts`）。

确认：

1. 设置页 LLM 配置能选 **custom**（若会员限制，见 `settings` 相关视图）

## 7. RAG 与 Embedding 说明

- 向量检索仍用 **Chroma**（`docker-compose.prod.yml` 内 `chromadb` 服务）  
- Embedding 由 Chroma 默认或 backend 侧模型生成（见 `backend/app/db/chroma.py`）  
- **PaddleOCR-VL 只负责「图片/PDF → 文本」**；文本 chunk 进入 Chroma 后，**Qwen 7B 负责生成答案**  

会计学知识库入库流程：

```
上传 PDF → knowledge API → run_pdf_ingest
  → PaddleOCR-VL 提取文本
  → chunker → Chroma + MySQL
```

## 8. 回滚方案

| 问题 | 操作 |
|------|------|
| vLLM 故障 | `.env` 设 `DEFAULT_LLM_PROVIDER=deepseek`，重启 backend |
| OCR 故障 | `PADDLE_OCR_VL_ENABLED=false`，走原 OCR 链路 |
| 全站回滚 | 保留上一版 Docker 镜像 tag + 旧 `.env` 备份 |
