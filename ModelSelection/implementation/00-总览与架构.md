# 00 — 总览与架构

## 1. 目标

在 **Economic Agent Platform** 中落地：

1. **Qwen 7B**（微调后）负责：对话、Agent 工具调用、会计学 RAG 综合回答  
2. **PaddleOCR-VL 1.6** 负责：PDF/图片文档解析 → 结构化文本 → 入库与附件上下文  
3. 平台（Docker）通过 **OpenAI 兼容 API** 与 **OCR 服务** 调用上述能力  

**不在本方案范围**：在 2核4G 轻量机上跑 7B 权重（需 GPU 机）。

---

## 2. 目标架构

```
                    ┌──────────────────────────────────────┐
                    │  用户浏览器                           │
                    └─────────────────┬────────────────────┘
                                      │ :8082
                    ┌─────────────────▼────────────────────┐
                    │  Agent Platform（Docker）              │
                    │  gateway + backend + MySQL + Chroma   │
                    │  + Redis + Neo4j（可选）              │
                    └───────┬──────────────────┬───────────┘
                            │                  │
              OpenAI API    │                  │ HTTP（内网）
              /v1/chat      │                  │
                            ▼                  ▼
              ┌─────────────────────┐  ┌─────────────────────┐
              │  vLLM               │  │  PaddleOCR-VL 1.6   │
              │  Qwen2.5-7B + LoRA  │  │  文档解析 API/CLI   │
              │  :8000              │  │  :8080（示例）       │
              └─────────────────────┘  └─────────────────────┘
                     GN7 T4 16G（可同机）
```

### 数据流（会计学 RAG）

```
PDF/图片上传
  → PaddleOCR-VL 1.6（Markdown/表格/公式）
  → 分块 + Embedding → Chroma
  → MySQL 元数据

用户提问
  → Chroma 检索 chunk
  → 组装 Prompt
  → vLLM Qwen 7B（微调）
  → 带 citations 的回答
```

## 4. 目录与资产规划

建议在 GPU 机（或共享 NAS）统一目录：

```text
/opt/models/
├── qwen/
│   ├── Qwen2.5-7B-Instruct/          # 基座
│   └── qwen7b-accounting-lora/       # 微调输出
├── paddle/
│   └── PaddleOCR-VL-1.6/             # OCR-VL 权重与配置
└── datasets/
    └── accounting_sft/               # build_accounting_sft.py 产出
        ├── train.json
        ├── eval.json
        └── manifest.json

ModelSelection/implementation/scripts/
├── build_accounting_sft.py           # 方案 1 数据构建
└── config/dataset_sources.yaml
```

平台侧（仓库内/服务器）：

```text
agent-platform/
├── .env                              # CUSTOM_* / OCR 服务地址
├── data/uploads/{user_id}/           # 用户文件
├── data/docker/chroma/               # 向量
└── deploy/docker-compose.prod.yml
```

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| T4 16G OOM | 7B 用 AWQ/GPTQ 4bit；OCR 与 vLLM 同机时限制 `max-model-len` |
| 微调过拟合 | 混合 10～20% 通用对话样本 |
| Paddle 与现有 `vlm.py` 并存 | 见 `04` 文档：新增 `PADDLE_OCR_VL_URL` 开关 |
| 4G 平台机 OOM | 平台用 4核8G；Neo4j 可阶段性关闭 |
