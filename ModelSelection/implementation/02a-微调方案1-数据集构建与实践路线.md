# 02a — 微调方案 1：开源数据集抽取 + 完整实践路线

## 1. 方案定位

**微调方案 1** = 从已确认的 **完整公开 Hugging Face 数据集** 中，抽取全部 **会计学 / 审计 / 财报表分析** 相关内容，经统一清洗、格式转换、分层混合后，用于 **Qwen2.5-7B QLoRA** 微调。

| 项 | 说明 |
|----|------|
| 基座 | Qwen2.5-7B-Instruct |
| 视觉 | PaddleOCR-VL 1.6（不入 SFT，走 RAG 入库） |
| 微调目标 | 审阅话术、CPA/准则问答风格、计算与工具调用、RAG 引用格式 |
| 准则原文 | **不进 SFT**，进平台 Chroma 知识库 |

**本方案不包含**：DISC-Fin-SFT 246k（未完整公开）、Kuaiji CAtAcctQA（未公开下载）。

## 3. 会计学相关判定规则

### 3.1 CFLUE 科目白名单（S3）

保留 `train` split 中满足任一：

- `名称 == "注册会计师"` 且 `科目 in {会计, 审计, 税法, 财务成本管理, 经济法, 公司战略与风险}`
- `名称 == "初级会计职称"`
- `名称` 含 `会计` 或 `审计`

**排除**：基金从业、期货、纯银行营销题（除非题干含报表分析关键词）。

### 3.2 关键词过滤器（S5～S8、ch05 子集）

```text
会计, 审计, 准则, 报表, 资产负债, 利润, 现金流, 存货, 折旧,
摊销, 减值, 凭证, 分录, 借贷, 科目, 毛利率, 净利率, 流动比率,
速动比率, ROE, ROA, 杜邦, 税, 增值税, 所得税, 注册会计师, CPA,
审阅, 内控, 合规, 财报, 三大报表, 所有者权益, 商誉, 合并报表
```

**排除关键词**（命中则丢弃，除非同时命中 ≥2 个会计关键词）：

```text
买入评级, 目标价, PE估值, 股价, 涨停, 区块链, 比特币, 期权定价
```

### 3.3 统一 Alpaca 输出字段

```json
{
  "instruction": "你是一名财务审阅助手。...",
  "input": "",
  "output": "...",
  "meta": {
    "source": "S1_sft-audit_regulation",
    "task": "audit_review",
    "lang": "zh"
  }
}
```

训练前删除 `meta`（LLaMA-Factory 不需要），保留于 `manifest.json` 统计。

## 4. 字段映射（各源 → Alpaca）

| 源 | 原始字段 | instruction | input | output |
|----|----------|-------------|-------|--------|
| S1 audit | instruction, system | `{system}\n{instruction}` 或 instruction | input | output |
| S2 accounting | Question, Complex_Cot, Response | 固定前缀 + Question | Complex_Cot（可选作 input） | Response |
| S3 CFLUE | question, choices, analysis, answer | question + 格式化选项 | "" 或 analysis 摘要 | `{analysis}\n\n**答案**：{answer}` |
| S4 ch05 | instruction, input, output | instruction | input | output |
| S5～S8 | instruction, output / conversations | 按源解析 | input 或上下文 | output / gpt 字段 |
| G1 tool | 合成 | 计算/分析请求 | 可选报表 JSON | 含 `<tool_call>...</tool_call>` |
| G2 rag | 合成 | 基于上下文回答 | `【检索上下文】\n...` | 结论 + `**参考来源**：...` |

### 4.1 工具格式（与平台 runtime 对齐）

```text
<tool_call>{"name":"calculator","arguments":{"expression":"1200/800"}}</tool_call>
<tool_call>{"name":"financial_ratio_calculator","arguments":{"data":"{...}","categories":"solvency"}}</tool_call>
<tool_call>{"name":"file_reader","arguments":{"path":"/uploads/1/report.pdf"}}</tool_call>
```

## 5. 混合比例与规模目标

| 层级 | 来源 ID | 占 train 比例 | 说明 |
|------|---------|---------------|------|
| L1 核心 | S1, S2, S3, S4 | **55～65%** | 审计 + 准则 + 考试解析 |
| L2 补充 | S5, S6, S7, S8 | **20～25%** | 推理与行业指令（已过滤） |
| L3 行为 | G1, G2 | **10～15%** | 工具 + RAG 引用 |
| L4 通用 | G3 | **5～10%** | 拒答、问候 |

| 档位 | train 条数 | 适用 |
|------|-----------|------|
| MVP | 3,000～5,000 | 首次 QLoRA 跑通 |
| 推荐 | 8,000～15,000 | 正式上线 |
| 上限 | 25,000～35,000 | S1 全量 + 过滤后补充（注意过拟合，增 G3） |

**eval**：从各源 **分层抽样 5%**，且 **CFLUE test 不得进入 train**。

## 6. 目录与脚本（仓库内）

```text
ModelSelection/implementation/
├── scripts/
│   ├── build_accounting_sft.py      # 一键构建 train/eval/manifest
│   ├── config/
│   │   └── dataset_sources.yaml     # 源开关、上限、关键词
│   └── requirements-sft-build.txt
├── 02a-微调方案1-数据集构建与实践路线.md   # 本文档
└── 02-Qwen7B微调指南.md              # QLoRA 训练（接本文档产出）
```

### 6.1 一键构建

```bash
cd ModelSelection/implementation/scripts
python -m venv .venv-sft
# Windows: .venv-sft\Scripts\activate
# WSL:     source .venv-sft/bin/activate
pip install -r requirements-sft-build.txt

python build_accounting_sft.py \
  --output-dir ~/datasets/accounting_sft \
  --profile recommended \
  --seed 42
```

产出：

```text
~/datasets/accounting_sft/
├── train.json              # LLaMA-Factory 用
├── eval.json
├── manifest.json           # 各源条数、过滤率
└── rejected_samples.jsonl  # 可选：被关键词排除的样本（调试）
```

### 6.2 复制到 LLaMA-Factory

```bash
cp ~/datasets/accounting_sft/train.json ~/LLaMA-Factory/data/accounting_sft.json
cp ~/datasets/accounting_sft/eval.json   ~/LLaMA-Factory/data/accounting_sft_eval.json
```

## 8. 微调 vs RAG（方案 1 边界）

| 进入 SFT（本脚本产出） | 进入 RAG（平台知识库） |
|------------------------|------------------------|
| 审阅意见结构、异常提示话术 | 《企业会计准则》全文 |
| 给定上下文如何作答（G2） | 税法、审计准则原文 |
| 工具何时调用、输出格式（G1） | 客户上传 PDF/报表 |
| CPA 题 **解析风格**（S3 analysis） | 具体公司历史财务数字 |
| 审计案例叙事（S1） | 法规修订（只更库不重训） |

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| S1 全量 30k 导致「只会写审计案例」 | 控制 S1 占比 ≤40%，增加 G1/G2/G3 |
| ODA 等含 CoT 过长 | `max_output_chars=4096`，截断或跳过 |
| 英文样本混入 | `lang=zh` 过滤 + 中文字符占比 >30% |
| 评测集泄露 | 脚本硬编码排除 CFLUE test、IDEAFinBench test |
| HF 下载失败 | 配置 `HF_ENDPOINT` 镜像；源级 `--skip-sources` |
