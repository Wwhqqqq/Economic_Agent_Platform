# 模型选型调研报告

**项目**：Economic Agent Platform（会计通用工作台）  
**调研日期**：2026-07-31  
**文档版本**：1.0  

---

## 1. 调研背景与场景定义

### 1.1 产品场景摘要

本平台面向 **财务/分析业务用户**，核心能力包括：

| 能力 | 说明 |
|------|------|
| Agent 对话与编排 | ReAct、Plan-Execute、多 Agent 辩论 |
| 技能与工具 | `/技能` 召唤、`file_reader`、计算器、代码执行等 |
| 知识库 RAG | PDF / 文本 / 图片入库、分块、向量检索、引用溯源 |
| 文件解析 | txt/csv/xlsx/json/pdf/图片；聊天附件 + 知识库两条路径 |
| 多用户隔离 | 租户级 uploads、知识文档、会话隔离 |
| 部署形态 | 腾讯云私有化部署为主，OpenAI 兼容 API 接入 |

### 1.2 目标架构（已确认方向）

```
┌─────────────────────────────────────────────────────────────┐
│  微调文本 LLM（主模型）                                       │
│  · 对话、推理、工具调用、技能编排、RAG 综合回答               │
└──────────────────────────▲──────────────────────────────────┘
                           │ 文本 / 结构化摘要
┌──────────────────────────┴──────────────────────────────────┐
│  视觉 / 文档解析模型（专用）                                  │
│  · 图片 OCR、图表理解、PDF 扫描页、票据/报表结构化            │
└──────────────────────────▲──────────────────────────────────┘
                           │ 原始文件
┌──────────────────────────┴──────────────────────────────────┐
│  规则解析层（非 LLM）                                         │
│  · pandas / PyPDF2 / 表格抽取 / 分块 / 向量索引               │
└─────────────────────────────────────────────────────────────┘
```

**结论**：该「双模型 + 解析管线」架构 **可行且与现有代码一致**（`custom` 文本 Provider + `pick_vision_provider` + ingestion 管线）。本报告在此前提下对比候选模型。

### 1.3 选型评价维度

| 维度 | 权重（本场景） | 说明 |
|------|:--------------:|------|
| 中文与领域文本能力 | ★★★★★ | 财报、审阅意见、政策表述 |
| 工具调用 / Agent | ★★★★★ | Function Calling、ReAct 稳定性 |
| 可微调性 | ★★★★★ | SFT/LoRA/QLoRA 生态与文档 |
| 私有化部署 | ★★★★☆ | vLLM/SGLang、显存与 QPS |
| 许可证 | ★★★★☆ | 商业使用、衍生模型、出海 |
| 文档/图表视觉 | ★★★★★ | OCR、表格、公式、图表 JSON |
| 推理成本 | ★★★☆☆ | MoE 激活参数、小模型优先 |
| 社区与迭代 | ★★★★☆ | HuggingFace、国内文档、案例 |

### 2.2 Qwen3 / Qwen3.5 / Qwen3.6（阿里通义）

**简介**：2025–2026 年国内 Agent 场景事实标准之一；尺寸 ladder 完整（0.6B–397B MoE），**Qwen-Agent** 框架与平台 Agent 架构高度同构。

| 项目 | 内容 |
|------|------|
| **推荐规格** | 微调首选 **Qwen3-14B/32B-Instruct** 或 **Qwen3-30B-A3B MoE**（推理成本低）；旗舰能力验证用 235B/397B MoE |
| **优势** | 中文与多语言最强梯队；工具调用模板成熟（`reasoning_content`、Function Call）；LLaMA-Factory / Swift / Unsloth 一等支持；Apache 2.0 无法律摩擦 |

| **微调** | SFT + DPO/GRPO；Agent 数据建议 ReAct/Tool Call 格式，混 10–20% 纯文本防过调用 |
| **与本平台** | 可通过 `custom` Provider + vLLM 部署；微调数据可覆盖 `financial_audit`、文档分析等技能 |

**适合度**：⭐⭐⭐⭐⭐（**综合首选**）

### 2.4 文本 LLM 推荐梯队

| 梯队 | 推荐 | 理由 |
|------|------|------|
| **第一首选** | **Qwen3-14B/32B-Instruct** 或 **Qwen3-30B-A3B MoE** | 中文 + Agent + 微调生态 + Apache 2.0 平衡最佳 |
| **推理增强备选** | **DeepSeek-R1-Distill-Qwen-32B** + LoRA | 复杂分析链、审阅推理；部署成本可控 |
| **长文档特化** | **Llama 4 Scout** | 单会话整库年报问答（若上下文长度是硬需求） |
| **合规/出海备选** | **Mistral Small 4** | 欧洲合规叙事、Apache 2.0 |
| **国内政企备选** | **GLM-4-9B/Plus** | 中文表达；须确认对外商用许可 |

**微调工程建议（2026 主流实践）**：

- 方法：**QLoRA**（GPU < 48GB）或 **LoRA r=16–32**（显存充足）
- 框架：**LLaMA-Factory**（中文文档全）或 **Swift**（ModelScope）
- 数据：≥1,000 条高质量样本；混合 Agent 轨迹 + 纯文本；含工具失败恢复样本
-  serving：**vLLM** + OpenAI 兼容 API → 对接本平台 `custom` Provider
- 评估：领域 benchmark + 人工抽检审阅意见质量

## 4. 组合方案推荐（针对本平台）

### 4.1 推荐组合 A — 生产私有化（平衡）

```
文本 LLM（微调）:  Qwen3-14B-Instruct + QLoRA（财务审阅 / Agent 技能）
视觉 / 文档:      PaddleOCR-VL-1.6（入库解析）+ Qwen2.5-VL-7B（聊天识图）
规则解析:         现有 pandas / PyPDF2 / file_reader（不变）
推理服务:         vLLM × 2 实例（text + vision）或 vision 仅 ingestion 批处理
```

| 优点 | 说明 |
|------|------|
| 成本可控 | 文档 0.9B + 文本 14B，单机多卡可跑 |
| 能力完整 | 报表 PDF、Excel、图片、Agent 工具全覆盖 |
| 许可证清晰 | Apache 2.0 为主 |
| 与现有代码 | `custom` + vision Provider + ingestion 管线改动最小 |

---

### 4.2 推荐组合 B — 推理优先

```
文本 LLM:  DeepSeek-R1-Distill-Qwen-32B + LoRA
视觉:      PaddleOCR-VL-1.6 + Qwen2.5-VL-7B
```

适合：复杂财务推理、多步审阅、协同决策辩论质量优先。

---

### 4.3 推荐组合 C — 快速验证（3–4 周 PoC）

```
文本 LLM:  Qwen3-14B 基础模型（暂不微调）via API 或本地 vLLM
视觉:      GPT-4o API 或 Qwen2.5-VL-7B 本地
```

验证产品流程与数据标注需求，再进入微调。

## 5. 文件解析能力：双模型能否覆盖？

**可以**，但需理解分工：

| 文件类型 | 解析方式 | 是否依赖 LLM | 是否依赖 VLM |
|----------|----------|:------------:|:------------:|
| txt / md / csv / json | 规则 + pandas | ❌ | ❌ |
| xlsx / xls | pandas / openpyxl | ❌ | ❌ |
| PDF（文本层） | PyPDF2 / pdfplumber | ❌ | ❌ |
| PDF（扫描件） | OCR → 可选 VLM 摘要 | ❌ | ✅ |
| PDF 内图表 | 切图 → VLM 结构化 | ❌ | ✅ |
| 独立图片 | PaddleOCR-VL / Qwen-VL | ❌ | ✅ |
| Word（docx） | 需补 python-docx 等 | ❌ | 可选 |

**文本 LLM 不直接「读文件」**，而是读 **解析后的文本 + RAG 检索结果 + 工具输出**。  
**视觉模型不替代 Excel 解析**，专注 **像素/document 图像**。

这与目标架构文档 [`docs/architecture/target/05-媒体资产与多模态解析.md`](../docs/architecture/target/05-媒体资产与多模态解析.md) 完全一致。

| 组件 | 模型 | 量化 | 显存（约） | 备注 |
|------|------|------|------------|------|
| 文本 LLM | Qwen3-14B | AWQ/GPTQ 4bit | 10–12 GB | 对话主服务 |
| 文本 LLM | Qwen3-32B | 4bit | 20–24 GB | 质量更高 |
| 视觉（文档） | PaddleOCR-VL-1.6 | FP16 | **2–4 GB** | 可 CPU/GPU |
| 视觉（聊天） | Qwen2.5-VL-7B | 4bit | 8–10 GB | 可与文本分时复用 GPU |

**腾讯云单机建议（生产试点）**：1× A10 24GB 或 2× 4090 — 文本 14B 4bit + PaddleOCR-VL 同机；Qwen-VL-7B 可按需启停或第二实例。

## 7. 与本平台集成清单（模型选定后）

| 步骤 | 动作 |
|------|------|
| 1 | `.env` 配置 `AGENT_DEFAULT_PROVIDER=custom` + 微调模型 vLLM 地址 |
| 2 | 视觉：ingestion 调用 PaddleOCR-VL；聊天附件调用 Qwen-VL |
| 3 | 扩展 `VISION_CAPABLE` 注册 self-host Qwen-VL |
| 4 | 准备微调数据：财务审阅对话、工具调用轨迹、拒答样本 |
| 5 | SFT/QLoRA → 合并或 LoRA 热加载 → vLLM Serving |
| 6 | 回归：知识库入库、聊天附件、file_reader、RAG 引用 |

## 8. 风险与注意事项

| 风险 | 缓解 |
|------|------|
| 微调过拟合工具调用 | 混合 10–20% 纯文本；工具子集随机化 |
| 视觉与文本模型版本漂移 | 优先同厂（Qwen + Qwen-VL）或固定解析输出 schema |
| GLM / DeepSeek / Llama 许可 | 上线前法务审阅；对外 SaaS 重点查 GLM、Llama MAU 条款 |
| PaddleOCR-VL 非对话模型 | 仅用于解析管线，不接入 `pick_vision_provider` 聊天多模态 |
| docx 等格式缺口 | 单独补解析器，不强行用 VLM |

---

## 9. 结论

1. **「微调文本 LLM + 独立视觉模型」** 对本平台 **完全可行**，且与现有架构一致。  
2. **文本 LLM 首选**：**Qwen3-14B/32B**（微调 + Agent + 中文 + 许可）；推理强化备选 **DeepSeek-R1 蒸馏版**。  
3. **视觉首选组合**：**PaddleOCR-VL-1.6**（文档/报表解析）+ **Qwen2.5-VL-7B**（聊天识图）。  
4. **文件解析** 由 **规则引擎 + 视觉模型 + 文本 LLM 三层** 共同完成，而非单一模型包打天下。  
5. 建议路径：**组合 C 验证 → 组合 A 微调上线 → 按业务反馈考虑组合 B 或更大规格**。
