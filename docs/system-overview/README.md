# 系统总览

## 项目定位

Agent Platform（会计学通用工作台）是一个面向**智能体编排与领域应用展示**的全栈平台。它以会计学场景（财务审计、报表分析、多方辩论）为主要演示领域，但底层架构是通用的：可注册工具、组合技能、切换执行模式、接入多种大模型，并通过 RAG 与多层记忆为 Agent 提供上下文。

## 整体架构

系统分为四层：

```
┌─────────────────────────────────────────────────────────┐
│  前端（Vue 3）                                           │
│  聊天 / 工具浏览 / 技能管理 / 知识库 / Agent 档案 / 设置  │
└───────────────────────────┬─────────────────────────────┘
                            │ REST + WebSocket
┌───────────────────────────▼─────────────────────────────┐
│  API 层（FastAPI）                                       │
│  聊天 WS、会话 CRUD、工具/技能/知识库/设置/认证/健康检查    │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│  核心能力层                                              │
│  AgentOrchestrator → ReAct / Plan-Execute / 辩论团队      │
│  MemoryManager → 三层记忆 + RAG 注入                     │
│  SkillRegistry / ToolRegistry → 能力与工具编排            │
│  LLMFactory → 多 Provider 大模型                         │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│  基础设施层                                              │
│  ChromaDB（向量：知识库 + 长期记忆）                       │
│  Neo4j（知识图谱 + 情景记忆）                              │
│  本地文件（data/ 目录、settings.json、audit.log）          │
└─────────────────────────────────────────────────────────┘
```

## 一次完整对话的请求链路

以用户在聊天页发送一条消息为例，后端处理顺序如下：

1. **WebSocket 接入**：客户端连接 `ws://host/ws/chat/{session_id}`，发送 JSON，包含用户输入、执行模式、可选技能名、Provider/模型等参数。

2. **技能激活（可选）**：若消息携带技能名，先在全局技能注册中心激活该技能。激活后，后续 Prompt 组装、工具筛选、记忆加载策略都会受技能配置影响。

3. **编排器路由**：`AgentOrchestrator` 根据用户指定的模式或「自适应」规则，选择具体 Agent：
   - 简单问答 → ReAct Agent
   - 含「分析、审计、报告」等关键词的复杂任务 → Plan-Execute Agent
   - 含「辩论、评审、委员会」等关键词 → 会计学辩论团队

4. **上下文组装**：Agent 启动前，`MemoryManager` 按策略加载：
   - 技能/Agent 的系统 Prompt
   - RAG 混合检索结果（知识库）
   - 长期向量记忆召回
   - Neo4j 图谱关联信息
   - 当前会话的短期对话历史

5. **ReAct 执行循环**（核心引擎）：大模型绑定可用工具后，进入「思考 → 决定是否调工具 → 执行工具 → 再思考」的循环，直到产出最终文本或达到最大迭代次数。

6. **流式事件推送**：执行过程中，后端以结构化事件（thinking、tool_call、reasoning、citation、final 等）推送给前端，实现 token 级展示与工具调用可视化。

7. **记忆持久化**：对话结束后，异步写入三层记忆（会话历史、长期向量、情景图谱），供后续轮次召回。

## 模块依赖关系

| 上游模块 | 下游/被依赖模块 | 关系说明 |
|----------|----------------|----------|
| Agent 编排 | 记忆、RAG、工具、技能、LLM | 编排器调度 Agent，Agent 运行时调用各模块 |
| 技能 | 工具、记忆 | 技能限定工具子集并定制 Prompt 与记忆策略 |
| 工具 | LLM（通过 ReAct 绑定） | 工具以 LangChain StructuredTool 形式供模型调用 |
| 记忆 | RAG、ChromaDB、Neo4j | 记忆管理器统一编排检索与写入 |
| RAG | ChromaDB、Neo4j | 向量与图谱分别存储，混合检索时融合 |
| 多 Agent | 工具、LLM、记忆 | 辩论角色各自运行带工具的 Prompt 循环 |
| API/前端 | 以上全部 | 提供用户交互入口与可视化 |

## 执行模式一览

平台对外暴露四种规范化的执行模式（内部另有 legacy 别名兼容）：

| 模式 key | 中文名 | 适用场景 | 底层 Agent |
|----------|--------|----------|------------|
| `adaptive` | 自适应 | 默认；由关键词自动路由 | 见下方路由规则 |
| `reasoning_action` | 推理行动 | 常规问答、单步工具调用 | ReAct Agent |
| `task_orchestration` | 任务编排 | 多步骤分析、审计、报告 | Plan-Execute Agent |
| `collaborative_decision` | 协同决策 | 多方观点碰撞、评审裁决 | 会计学辩论团队 |

**自适应路由规则**：编排器扫描用户输入中的关键词。出现「辩论、讨论、评审、委员会」等 → 协同决策；出现「分析、审计、评估、报告、尽调」等 → 任务编排；否则 → 推理行动。

## 启动与注册机制

应用启动时（`main.py`）会完成两类自动注册：

- **工具注册**：10 个内置工具（5 个通用 + 5 个会计学）写入 `ToolRegistry`。
- **技能注册**：3 个内置技能（文档分析、数据可视化、财务审计）写入 `SkillRegistry`。

此后所有 Agent 执行、API 列表查询、前端展示都基于这两个注册中心的全局状态。

## 数据存储分布

| 数据类型 | 存储位置 | 用途 |
|----------|----------|------|
| 会话消息 | 进程内存（ShortTermMemory） | 当前会话上下文窗口 |
| 跨会话记忆 | ChromaDB `long_term_memory` 集合 | 语义相似度召回历史片段 |
| 知识库文档 | ChromaDB `knowledge_base` 集合 | RAG 向量检索 |
| 实体与关系 | Neo4j 图数据库 | 知识图谱检索 + 情景记忆 |
| LLM 配置覆盖 | `data/settings.json` | 用户在前端修改的 Provider 配置 |
| 审计日志 | `data/audit.log` | 登录、上传、设置变更等操作记录 |

## 实现说明（与宣传口径的差异）

- 项目依赖中包含 LangGraph，但**当前代码中的执行引擎是手写 ReAct 循环**，并未使用 LangGraph 的 StateGraph。Agent 可通过 LCEL 暴露 `Runnable` 接口，但主聊天链路不经过 LangGraph。
- 长期向量记忆在本地 Chroma 模式下默认关闭（避免首次启动下载 embedding 模型），连接 Docker 远程 Chroma 时自动开启。
- Neo4j 不可用时，图谱相关功能静默降级，健康检查会报告 `degraded` 而非直接崩溃。
