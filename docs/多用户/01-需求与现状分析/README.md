# 01 — 需求与现状分析

## 1. 业务目标

将 Agent Platform 从「单机演示 / 单账号」升级为「**多用户 + 会员制** 智能体工作台」：

- 用户可**自主注册**为普通用户并登录
- 每位用户拥有**私有**会话、记忆、知识库，互不串数据
- **会员用户**在普通用户能力之上，获得高级 Agent 模式、会员专享知识库、更高配额
- 通过会员差异实现商业化，**不在应用内建设管理员后台**

本需求对应常见的 **Freemium + 订阅会员** SaaS 模型（如 Notion 免费版/Plus、ChatGPT Free/Plus）。

## 2. 用户类型定义（仅两类）

| 类型 | 标识 `user_type` | 获得方式 | 定位 |
|------|------------------|----------|------|
| **普通用户** | `regular` | 注册即默认 | 体验核心聊天与基础能力 |
| **会员用户** | `member` | 付费开通 / 兑换码 / 运维脚本 | 完整 Agent 能力与会员知识库 |

**明确不包含**：

- 管理员（admin）、超级管理员、运营后台
- 应用内的用户管理、封禁、灌库 UI（由运维 / Webhook / 脚本完成）

**匿名访客**：仅当 `AUTH_ENABLED=false` 时用于本地开发；生产关闭。

## 3. 普通用户 vs 会员用户 — 能力差异

### 3.1 功能权限

| 能力 | 普通用户 | 会员用户 |
|------|----------|----------|
| 注册 / 登录 / 改密 | ✓ | ✓ |
| 私有对话会话 | ✓（有上限） | ✓（更高或无上限） |
| 推理行动（ReAct） | ✓ | ✓ |
| 自适应路由 | ✓（仅路由到 ReAct） | ✓（可路由全部模式） |
| 任务编排（Plan-Execute） | ✗ | ✓ |
| 协同决策（多 Agent 辩论） | ✗ | ✓ |
| 基础技能（文档分析等） | 部分 | ✓ 全部 |
| 财务审计等高阶技能 | ✗ | ✓ |
| 私有知识库上传 / 检索 | ✓（有配额） | ✓（更高配额） |
| **会员专享知识库 RAG** | ✗ | ✓ |
| 个人 LLM API Key 配置 | ✗ 或只读默认 | ✓ 完整配置 |
| code_executor 工具 | ✗ | ✓（可配置） |

### 3.2 配额差异（示例，可配置）

| 配额项 | 普通用户 | 会员用户 |
|--------|----------|----------|
| 最大会话数 | 20 | 500 |
| 知识库文档数 | 10 | 200 |
| 单文件大小 | 5 MB | 20 MB |
| 每日 WS 消息数 | 100 | 2000 |
| 长期记忆条数 | 关闭或 50 | 开启，500+ |

配额存 `system_settings` 或配置文件，按 `user_type` 读取；会员过期后降级为普通用户配额。

### 3.3 会员有效期

- `membership_expires_at`：NULL 表示非会员或终身（按业务定）
- 登录 / 每次请求校验：若 `user_type=member` 且已过期 → **自动降级为 regular**（或保留 member 标识但按 regular 门控，推荐前者）
- 续费：支付 Webhook 更新 expires_at

## 4. 功能需求清单

### 4.1 身份与账号

- 开放注册（默认普通用户）
- 登录、登出、改密、可选 Refresh Token
- 账号状态：active / disabled（disabled 由运维改库或 Webhook）
- 登录失败锁定

### 4.2 会话与聊天

- 服务端创建 session，绑定 user_id
- WebSocket 必须鉴权 + 归属校验
- 普通用户调用会员专属 mode → 返回 403 + 友好提示升级

### 4.3 记忆与知识

- 全用户：短期 / 长期 / 情景记忆按 user_id 隔离
- 私有知识库：owner 可 CRUD
- **会员专享知识库**：运维灌库，visibility=member，仅会员 RAG 可检索

### 4.4 会员开通

- `GET /api/membership/status`：当前类型、到期时间
- `POST /api/membership/webhook`：支付平台回调（签名校验），更新 user_type
- 前端「升级会员」跳转支付页（Phase 4+）

### 4.5 安全

- REST / WS 统一鉴权
- 敏感操作审计（用户仅可看自己的 audit）
- API Key 加密存储（**仅会员**可配置个人 Key，或普通用户用平台 Key）

## 5. 现状差距分析

（与单租户对比，_admin 相关差距项已移除_）

| 模块 | 现状 | 差距 |
|------|------|------|
| 认证 | .env 单账号 | MySQL users + user_type |
| WebSocket | 无 Token | 握手鉴权 + 功能门控 |
| 会话 | 内存全局 | MySQL + user_id |
| 记忆 / RAG | 无 tenant | user_id filter + 会员库 |
| 执行模式 | 全员可用 | 高级模式 require member |
| 配置 | 全局 settings.json | 会员个人 LLM 配置 |
| 前端 | 无会员态 | 展示会员标识、升级入口 |

## 6. 不在初版范围内

- 应用内管理后台
- 组织 / 部门 / 多角色 RBAC
- OAuth / 企业 SSO（Phase 4+）
- 完整支付收银台（仅 Webhook 接口 + 人工开通）
- 按 Token 精确计费

初版聚焦：**隔离 + 两级用户 + 会员门控**。

## 7. 成功标准（验收）

1. 用户 A 无法访问用户 B 的会话与私有知识库
2. 普通用户无法使用 Plan-Execute / 多 Agent / 会员专享 RAG
3. 会员过期后自动失去会员能力
4. 会员用户可使用全部执行模式并检索会员知识库
5. 双实例部署会话一致
6. 无明文密码、无 API Key 泄露
