# 多用户体系 — 设计文档导航

本目录是 Agent Platform **从单租户演示系统演进为多用户生产系统**的完整设计说明。仅包含架构、策略与数据模型设计，**不涉及具体代码实现**。

## 背景

当前系统具备可选的单账号 JWT 登录（`.env` 配置），但会话、记忆、知识库、LLM 设置均为**全局共享**，WebSocket 未鉴权，无法满足：

- 多用户独立登录与数据隔离
- **普通用户与会员用户**差异化能力与配额
- 安全存储凭证与敏感配置
- 多实例部署下的并发与一致性

本设计以 **MySQL 8.0** 作为关系型主库，与现有 **ChromaDB + Neo4j** 协同，采用「**MySQL 管身份与元数据，向量/图谱管语义数据，全链路 user_id 租户隔离**」的业界常见模式。

## 用户类型（核心前提）

全文档仅考虑**两类用户**，不设管理员、超级管理员等后台角色：

| 类型 | 标识 | 定位 |
|------|------|------|
| **普通用户** | `regular` | 默认注册类型；基础对话与私有知识库 |
| **会员用户** | `member` | 付费或开通会员；高级 Agent 能力 + 会员专享知识库 |

平台级配置、会员知识库入库、会员开通/续费由**运维脚本或外部支付回调**处理，不在应用内做后台管理界面。

## 设计原则（贯穿全文）

1. **仅两类用户**：普通用户与会员用户；权限差异通过 `user_type` + 配额 + 功能门控实现。
2. **默认私有**：用户只能访问自己的会话、记忆、私有知识库。
3. **会员增值**：会员专享知识库、高级执行模式、更高配额，作为商业化核心。
4. **服务端权威**：`user_id`、`user_type` 只从已验证 Token 解析。
5. **无应用内管理端**：平台配置走环境变量；会员开通走支付 Webhook；知识库灌库走运维脚本。
6. **可渐进落地**：分阶段交付，每阶段可独立上线、可回滚。

## 关键决策摘要

| 决策项 | 选定方案 |
|--------|----------|
| 用户类型 | **regular（普通）** + **member（会员）** |
| 关系型数据库 | MySQL 8.0 |
| 认证协议 | JWT Access Token + 可选 Refresh |
| 租户模型 | 单库行级 `user_id` 隔离 |
| 会员知识库 | visibility=`member`，**仅会员可 RAG 检索** |
| 会员开通 | 外部支付 Webhook 更新 `user_type` / `membership_expires_at` |
| WebSocket 鉴权 | 连接时校验 Token，绑定 user_id |

详细论证见各子文档。
