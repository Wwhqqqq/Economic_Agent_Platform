# 02 — Phase 2 目标与范围

## 1. 业务目标

让平台从「单租户演示级知识共享」升级为「**多用户私有数据隔离**」：

- 用户 A 上传的知识、产生的长期/情景记忆，用户 B **不可见、不可搜、不可删**
- 对话上下文中的 RAG 检索 **仅命中当前用户私有库**
- 多用户并发时 **skill 激活不互相覆盖**

会员差异化（会员库、高级 Agent、配额）留给 **Phase 3**，Phase 2 只打隔离地基。

## 3. 架构原则（实施时遵守）

### 3.1 数据权威源

```
MySQL knowledge_documents  = 元数据权威（doc_id, user_id, visibility, title）
Chroma knowledge_base    = 向量副本（metadata 必须含 user_id, visibility, doc_id）
Neo4j Document/Entity    = 图谱副本（节点属性含 user_id, visibility, doc_id）
```

**写入顺序建议**：MySQL 事务成功 → Chroma → Neo4j（任一步失败需可补偿或标记 failed）。

### 3.2 检索 filter（Phase 2 唯一合法条件）

**普通用户与会员用户在 Phase 2 行为相同**（都只查自己的 private）：

```
(user_id = current_user_id AND visibility = 'private')
```

Phase 3 将在同一函数内为 member 扩展 OR 条件，**Phase 2 禁止**普通用户路径传入 member filter。

### 3.3 记忆与会员无关

短/长/情景记忆 **只认 `user_id`**，不认 `user_type`。文档 [06 — 记忆与 RAG 隔离](../../06-记忆与RAG隔离/README.md) 已明确。

## 6. 非目标（Scope 外）

- 不做管理后台、运维 UI
- 不做支付 / Webhook / 兑换码
- 不做 API Key 加密（Phase 4）
- 不做 audit_logs 入库（Phase 4）
- 不重构 Agent 编排模式（除 skill 上下文外）
- 不追求 Neo4j 性能优化（隔离正确优先）
