# 06 — 环境与分支约定

---

## 1. 本地开发环境

### 1.1 最低配置（Phase 2 负责人）

| 组件 | 方式 | 说明 |
|------|------|------|
| Python 3.11+ | 本机 | `pip install -r backend/requirements.txt` |
| MySQL 8 | 本机或 Docker | `DATABASE_URL` 指向 `agent_platform` |
| Chroma | Docker `:8001` 或嵌入式 | 向量隔离 **必须** 可测 |
| Neo4j | Docker 可选 | 图谱隔离推荐测；不可用先测向量路 |
| Node 18+ | 前端 | `npm install && npm run dev` |

### 1.2 启动顺序（本地）

```bash
# 1. 基础设施（若用 Docker）
docker compose up -d mysql redis chromadb neo4j

# 2. 迁移
cd backend && alembic upgrade head

# 3. 后端
uvicorn main:app --reload --host 0.0.0.0 --port 8000

# 4. 前端
cd frontend && npm run dev
```

### 1.3 关键环境变量（`.env` 摘录）

```env
DATABASE_URL=mysql+aiomysql://root:xxx@localhost:3306/agent_platform?charset=utf8mb4
CHROMA_HOST=localhost
CHROMA_PORT=8001
NEO4J_URI=bolt://localhost:7688
AUTH_ENABLED=true
DEEPSEEK_API_KEY=sk-xxx          # 对话类回归需要
ENABLE_VECTOR_MEMORY=true        # 测长期记忆时显式开启（本地 Chroma 非 HTTP 时）
```

## 2. Git 分支策略

| 分支 | 用途 | 生命周期 |
|------|------|----------|
| `main` | 稳定可部署 | 长期 |
| `feature/phase2-rag-isolation` | Phase 2 全部工作 | 合并后删除 |
| `feature/phase3-membership` | 组员 Phase 3 | 与 P2 并行 |

### 2.1 Commit 规范（建议）

```
feat(phase2): add knowledge_documents migration
feat(phase2): tenant filter for chroma retrieve
fix(phase2): file_reader path traversal
test(phase2): manual acceptance case 2
docs(phase2): update acceptance record
```

### 2.2 PR 要求

- 标题前缀 `[Phase 2]`
- 描述中链接本目录相关 Step
- 附 [05-测试与验收](./05-测试与验收.md) 验收表截图或勾选
- 若改 `retrieve` 签名，@ Phase 3 负责人 review

## 6. Phase 3 组员无 Docker 时的环境

| 需求 | 方案 |
|------|------|
| MySQL | 本机安装 MySQL 8，导入 schema（`alembic upgrade head`） |
| Backend | `uvicorn` 直连本机 MySQL |
| Chroma/Neo4j | 暂不需要；会员 RAG 联调用共享测试服 |
| 前端 | `npm run dev`，API 指向本机 `:8000` 或测试服 |

组员 Phase 3 **门控/API/前端** 开发不依赖 Docker；详见 [04](./04-Phase3协作接口.md) 第 7 节。
