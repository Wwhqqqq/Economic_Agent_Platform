# 04 — 工具系统

工具（Tool）是 Agent 与外部世界交互的**原子能力单元**。本项目实现了完整的工具抽象、注册、发现和 LangChain 桥接机制。

---

## 1. 设计目标

| 目标 | 实现方式 |
|------|----------|
| 统一接口 | 所有工具继承 `BaseTool` |
| 动态管理 | `ToolRegistry` 单例注册中心 |
| LLM 可调用 | 转换为 LangChain `StructuredTool` |
| 结构化输入 | Pydantic Schema 验证参数 |
| 分类管理 | category 字段：general / accounting / web 等 |
| 可观测 | 执行日志 + WebSocket 事件推送 |

---

## 2. BaseTool 抽象

**文件：** `backend/app/tools/base.py`

```python
class BaseTool(ABC):
    name: str = ""              # 唯一标识，LLM 通过此名调用
    description: str = ""       # 功能描述，LLM 选工具的依据
    category: str = "general"   # 分类
    requires_confirmation: bool = False  # 预留：执行前需用户确认

    @abstractmethod
    async def _execute(self, **kwargs) -> ToolResult:
        """子类实现核心逻辑"""
        ...

    def get_input_schema(self) -> type[BaseModel]:
        """Pydantic 输入模型，自动生成 JSON Schema 给 LLM"""
        return BaseModel

    def to_langchain_tool(self) -> StructuredTool:
        """转为 LangChain 工具"""
        ...

    async def execute(self, **kwargs) -> ToolResult:
        """外部调用入口，含日志和异常捕获"""
        ...
```

### 2.1 ToolResult 结构

```python
@dataclass
class ToolResult:
    success: bool
    data: Any
    error: Optional[str] = None

    def to_string(self) -> str:
        # 成功返回 str(data)，失败返回 "Error: ..."
```

LLM 收到的 Observation 始终是字符串形式。

### 2.2 双路径执行

工具支持两种调用路径：

| 路径 | 调用方 | 场景 |
|------|--------|------|
| 异步直接调用 | `runtime.execute_tool_call()` | ReAct 循环主路径 |
| LangChain StructuredTool | `llm.bind_tools()` | Function Calling 绑定 |

`_sync_execute_wrapper()` 处理 LangChain 同步接口与 asyncio 的兼容。

## 3. ToolRegistry 注册中心

**文件：** `backend/app/tools/registry.py`  
**模式：** 单例

### 3.1 核心 API

| 方法 | 作用 |
|------|------|
| `register(tool)` | 注册工具实例 |
| `unregister(name)` | 卸载工具 |
| `get(name)` | 按名获取 |
| `get_by_category(category)` | 按分类筛选 |
| `list_all()` | 返回元数据列表（供 API / 前端） |
| `to_langchain_tools(categories, names)` | **关键**：转为 LangChain 工具列表 |

### 3.2 工具筛选逻辑

```python
def to_langchain_tools(categories=None, names=None):
    for tool in self._tools.values():
        if categories and tool.category not in categories:
            continue
        if names and tool.name not in names:
            continue
        tools.append(tool.to_langchain_tool())
    return tools
```

**应用场景：**
- ReAct Agent：默认全部工具（或技能筛选后的子集）
- 辩论团队：`categories=["accounting", "general", "web"]`
- 财务审计技能：通过 Skill 的 `get_required_tools()` 限定

### 3.3 启动注册

`main.py` → `register_all_tools()` 在应用启动时注册全部 10 个工具：


## 5. 工具调用全链路

```
1. LLM 决定调用工具
   └─ response.tool_calls = [{ name, args, id }]

2. runtime.execute_tool_call(tool_call)
   ├─ tool_registry.get(tool_name)
   ├─ tool.execute(**tool_args)
   └─ 返回 ToolMessage(content=result_string)

3. ToolMessage 追加到 messages 列表
   └─ 下一轮 LLM 推理可看到 Observation

4. 同时 yield WebSocket 事件
   ├─ TOOL_CALL { tool, args }
   └─ TOOL_RESULT { tool, result }
```

## 6. 如何扩展新工具

只需 3 步：

**Step 1：** 创建工具类

```python
# app/tools/my_tool.py
from pydantic import BaseModel, Field
from app.tools.base import BaseTool, ToolResult

class MyToolInput(BaseModel):
    query: str = Field(description="查询内容")

class MyTool(BaseTool):
    name = "my_tool"
    description = "做某件事的工具"
    category = "general"

    def get_input_schema(self):
        return MyToolInput

    async def _execute(self, query: str) -> ToolResult:
        result = do_something(query)
        return ToolResult(success=True, data=result)
```

**Step 2：** 在 `main.py` 注册

```python
from app.tools.my_tool import MyTool
tool_registry.register(MyTool())
```

**Step 3：** 重启后端，Tools 页面自动展示

## 7. 设计模式总结

| 模式 | 应用 |
|------|------|
| **抽象工厂** | BaseTool 定义接口，子类实现 |
| **单例** | ToolRegistry 全局唯一 |
| **策略** | 不同 category 的工具可被不同 Agent/Skill 选用 |
| **适配器** | `to_langchain_tool()` 桥接自定义工具与 LangChain |

---

## 8. 答辩要点

**强调：**
- 会计工具是**确定性计算**，不依赖 LLM 幻觉，保证数字准确
- Pydantic Schema 让 LLM 知道每个参数的含义和类型
- Registry 模式让工具可插拔，符合开闭原则

**注意：**
- `requires_confirmation` 字段已定义但未在运行时启用
- 暂无 HTTP API 动态注册工具（仅代码级 register）

**演示建议：**
- 打开 `/tools` 页面展示 10 个工具
- 在 Chat 中问「帮我搜索最新会计准则」观察 web_search 调用
