# 05 — 技能系统

技能（Skill）是比工具更高级的**复合能力抽象**，将 Prompt 策略、工具组合、上下文策略打包为可激活的「专业能力包」。

---

## 1. 工具 vs 技能

| 维度 | 工具 (Tool) | 技能 (Skill) |
|------|------------|--------------|
| 粒度 | 原子操作 | 复合能力 |
| 示例 | 计算 ROE | 完整财务审计 |
| 组成 | 单一功能 | 多工具 + Prompt + 策略 |
| 激活方式 | Agent 自动选择 | 用户/系统显式激活 |
| 执行方式 | ReAct 循环中调用 | Pipeline 或 ReAct |

```
工具：  calculator, balance_sheet_analyzer, ...
技能：  financial_audit = Prompt + [5个会计工具] + 审计流水线 + 上下文策略
```

## 2. BaseSkill 抽象

**文件：** `backend/app/skills/base.py`

```python
class BaseSkill(ABC):
    name: str = ""
    description: str = ""
    category: str = "general"
    icon: str = "🔧"

    @abstractmethod
    def get_system_prompt(self) -> str:
        """技能专用 System Prompt，注入 Agent 系统消息"""

    @abstractmethod
    def get_required_tools(self) -> list[str]:
        """技能依赖的工具白名单"""

    @abstractmethod
    async def execute(self, user_input, **kwargs) -> SkillResult:
        """技能执行入口"""

    def get_context_strategy(self) -> dict:
        """控制记忆/RAG 注入策略"""
        return {
            "max_history": 20,
            "include_knowledge": True,
            "include_entities": True,
            "include_long_term": True,
        }
```

### 2.1 技能的三层配置

```
┌─────────────────────────────────────┐
│  Layer 1: System Prompt             │
│  领域指令、输出格式、分析方法论         │
├─────────────────────────────────────┤
│  Layer 2: Tool Filter               │
│  限定 Agent 只能使用指定工具           │
├─────────────────────────────────────┤
│  Layer 3: Context Strategy          │
│  控制记忆/RAG/图谱是否注入上下文       │
└─────────────────────────────────────┘
```

## 3. SkillRegistry 技能注册中心

**文件：** `backend/app/skills/registry.py`

| 方法 | 作用 |
|------|------|
| `register(skill)` | 注册技能 |
| `activate(name)` | 激活技能（全局单激活） |
| `deactivate()` | 取消激活 |
| `get_active()` | 获取当前激活技能 |
| `list_all()` | 列出所有技能 |

**激活机制：** 同一时刻只有一个技能处于激活状态。激活后：
- `runtime.resolve_system_prompt()` 合并技能 Prompt
- `runtime.get_langchain_tools()` 按 `get_required_tools()` 筛选工具
- `memory_manager.load_context()` 按 `get_context_strategy()` 控制上下文

## 4. 内置技能详解

### 4.1 financial_audit — 财务审计

**文件：** `backend/app/skills/builtin/financial_audit.py`  
**类别：** accounting  
**执行方式：** **固定 Pipeline（流水线）**

#### 审计流水线

`SkillExecutor.run_financial_audit_pipeline()` 按顺序执行：

```
Step 1: balance_sheet_analyzer  action=verify     → 验证 A = L + E
Step 2: balance_sheet_analyzer  action=analyze    → 资产负债结构
Step 3: income_statement_analyzer action=analyze  → 利润表分析
Step 4: cash_flow_analyzer      action=analyze    → 现金流分析
Step 5: financial_ratio_calculator              → 综合财务比率
Step 6: dupont_analysis                         → 杜邦 ROE 分解
Step 7: LLM 汇总                                → 生成审计报告
```

#### 报告结构（Prompt 约束）

LLM 被要求输出包含以下章节的 markdown 报告：

- **Executive Summary** — 执行摘要
- **Financial Health Score (0-100)** — 健康评分
- **Detailed Analysis** — 详细分析
- **Risk Flags** — 风险标记
- **Recommendations** — 建议

#### 触发条件

`SkillExecutor.execute_skill()` 检测到：
1. 技能名为 `financial_audit`
2. 用户输入中包含 JSON 格式的财务数据（`extract_json_blob()`）

→ 走 Pipeline；否则 fallback 到 ReAct。

### 4.2 document_analysis — 文档分析

**类别：** document  
**执行方式：** ReAct（Agent 自主决定工具调用顺序）

适用：PDF/文档内容提取、摘要、结构化分析。

### 4.3 data_visualization — 数据可视化

**类别：** data  
**执行方式：** ReAct

适用：通过 code_executor 生成图表代码、数据处理和可视化建议。

## 5. 两种执行范式对比

| 范式 | 代表技能 | 特点 | 适用场景 |
|------|----------|------|----------|
| **Pipeline（流水线）** | financial_audit | 步骤固定、结果可预测、不依赖 LLM 规划 | 标准化审计流程 |
| **Emergent（涌现式）** | document_analysis | LLM 自主决定工具和顺序 | 开放式文档任务 |

**答辩话术：**  
> 技能系统支持两种执行范式。财务审计这类有明确 SOP 的场景，我们用 Pipeline 保证每步都执行到位；文档分析这类开放任务，交给 ReAct 让 LLM 自主编排。这是「可控性」与「灵活性」的权衡。

## 10. 常见问题

**Q: 技能和 Plan-Execute 有什么区别？**  
A: 技能是**领域能力包**（Prompt + 工具 + 策略），Plan-Execute 是**通用任务编排引擎**。财务审计技能内部用 Pipeline 而非 Plan-Execute，因为审计步骤是固定的。

**Q: 能同时激活多个技能吗？**  
A: 当前设计为单激活。多技能场景可通过组合 Prompt 或新建复合技能实现。
